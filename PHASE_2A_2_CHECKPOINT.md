# Phase 2A.2 — AI-first semantic analyzer architecture

Date: 2026-10-07. Branch: `feature/elearning-studio-phase-2a`.

ARCHITECTURE: `LessonAnalysisProvider` now requires `id`, `name`, and `analyze(document, options?)`. `LessonAnalysisOptions` carries progress and cancellation. `LessonAnalysisService` prefers a configured semantic provider, validates its result, and falls back to the deterministic provider. The wizard uses this service; no vendor SDK or network adapter is installed. The concrete local analyzer retains its old callback overload for existing callers.

SEMANTIC INPUT: `buildSemanticAnalysisInput` returns the entire ordered document as structured JSON, retaining block IDs, heading levels, paragraph text, lists, numbering, tables, rows, cells, paragraph breaks, column coordinates and merged spans. It rejects duplicate block IDs and structurally empty DOCX. Local heading and GV/HS classification hints are advisory and accompany the complete source, never replace it. Source text is explicitly described as untrusted data. The DOCX extractor is unchanged in this phase.

AI CONTRACT: `semantic.ts` exports strict Zod schemas and TypeScript types for `AiPedagogicalAnalysisResult`, `AnalysisItem` and `TeachingActivityAnalysis`, plus `aiAnalysisJsonSchema()` for future structured-output adapters. All requested top-level groups are mandatory; identity fields are optional. Activities have title provenance, stage, duration and separate content, teacher/student, goals, products and organization items. Every AnalysisItem requires source block IDs and bounded confidence. Reasoning codes are restricted to five short enums; extra fields and arbitrary reasoning prose are rejected.

VALIDATION: A connection returns `unknown`. `SemanticLessonAnalysisProvider` validates the contract before normalization into a separately validated `PedagogicalAnalysis`. Unknown source IDs are rejected. Missing metadata remains empty/null; curriculum is never synthesized. Accepted items retain indexed classification paths and source traces for every referenced block. No LessonProject is read or mutated by this pipeline. Provider errors are not logged or presented verbatim.

FALLBACK: Unconfigured, unavailable and malformed semantic responses use deterministic analysis. Cancellation propagates and never triggers fallback. Default production status is `AI chưa được kết nối`; local output says `Phân tích cục bộ` and `Đang dùng chế độ phân tích cơ bản.` Connection failures say AI is temporarily unavailable. `PersonalAiSettings` defines only provider ID, model and connection status; no credential fields or persistence were added. The mock exists only under `tests/support`, has a development-only marker, and is rejected by production service mode. Its results never receive the real-AI badge.

REVIEW UI: Heading is `Đã phân tích kế hoạch bài dạy`. A compact summary shows detected identity information, outcomes/knowledge, competencies, qualities, activities and AI integration. Successful editable sections come before detailed diagnostics. Medium-confidence fields display `Nên kiểm tra`. Attention summaries and unresolved content are collapsed initially; provenance remains expandable. Existing edit, correction, cancellation and mandatory confirmation controls remain functional. Source badges are service metadata rather than part of exported lesson content.

CONFIDENCE: >= 0.85 accepted; >= 0.60 and < 0.85 accepted with review marks; < 0.60 retained in unmapped content and correction controls. Explicit uncertainItems remain uncertain regardless of supplied score. Structural-only headings/lead-ins are excluded from uncertain instructional content. The fallback received only small structural fixes: terminal heading punctuation, objective lead-ins retaining their parent section, and explicit AI labels retaining their competency code. Local heuristic scores are not calibrated probabilities. No broad semantic regex expansion was made.

REAL DOCX REGRESSION: Existing 43 corrective regression tests and both real DOCX fixtures preserved and PASS. New tests also verify full structured input equality for the real table document (five GV/HS tables) and synthetic merged-cell structure. Existing Phase 1 tests remain PASS. This does not establish real-model semantic accuracy: no real AI service was called and the exact originally failing teacher document has not been supplied in this phase.

TESTS: `npm test -- --run` — PASS, 259/259 tests across 8 files. Includes 22 semantic architecture tests and an additional functional wizard test covering semantic service injection, source badge, medium confidence and collapsed uncertain review. Existing 236 tests preserved; heading assertions migrated to the requested UI heading.

BUILD: `npm run build` — PASS (TypeScript and Vite production). Existing two non-fatal Zod PURE annotation warnings remain. No mock provider is included in production assets.

KNOWN LIMITATIONS: Production currently uses deterministic fallback because real AI is deliberately not connected. Mock fixtures verify contracts/orchestration, not language understanding. A future adapter must implement model access, connection verification, timeouts/context limits and whole-document semantic behavior. Identity follows the requested contract without item-level confidence/source IDs; model-returned identity values still require teacher verification. Item provenance validates block existence, not semantic truth; table provenance currently identifies the full table block rather than an AI-selected cell. PDF/OCR and nested-table semantic support retain prior limitations. Drafts remain session-only. No secret storage, Settings UI, blueprint generation, lesson generation, slides, image features, SCORM, ZIP or Phase 2B work was added.

Git at the implementation checkpoint: No commit or push had been performed. Prior corrective-pass working changes were preserved.
